# Provenance

`sanity-sc-rs` is a clean-room implementation of the Sanity method. This file
records what was read, by whom, and under which licence, so the basis for the
MIT licence on this crate is auditable.

## Sources used

| source | licence | used for |
|---|---|---|
| Breda, Zavolan, van Nimwegen. *Bayesian inference of gene expression states from single-cell RNA-seq data.* Nature Biotechnology 39(8):1008-1016 (2021). doi 10.1038/s41587-021-00875-x | (c) The Author(s), exclusive licence to Springer Nature. Not open access. | the model, the motivation, the output definitions |
| Supplementary Information to the above, sections S1.1 to S1.3 | same | every equation in `docs/SPEC.md` |
| Corless, Gonnet, Hare, Jeffrey, Knuth. *On the Lambert W function.* Adv. Comput. Math. 5:329-359 (1996) | journal article | the Wright omega solve in `src/utils/wright_omega.rs` |

The paper is behind a subscription and is not CC licensed. This matters for how
the specification is written, not for whether the method may be implemented.
Copyright subsists in the authors' text, figures and choice of exposition. It
does not subsist in the mathematics. 17 USC 102(b) and EU Software Directive
Art. 1(2) both exclude procedures, processes, methods of operation and
mathematical concepts from copyright. A Bayesian model, a Laplace approximation
and a digamma identity are facts, and facts are not owned.

So `docs/SPEC.md` **restates** the mathematics in our own notation and our own
prose, and cites the SI equation numbers as references. It does not transcribe SI
paragraphs verbatim. Where our notation differs from theirs, that is deliberate
and the spec says so.

## Sources deliberately not used

`jmbreda/Sanity` is licensed **GPL-3.0**, repo-wide. A C++ to Rust port is a
derivative work under section 5 of that licence and would have to ship GPL-3.0.
Every crate this one is meant to feed (`bixverse-rs`, `bonsai-rs`,
`ann-search-rs`, `edge-rs`) is MIT, and an R package built on a GPL-3.0 static
library is a GPL-3.0 R package. That is not the licence position anyone here
wants, so the port route is closed.

**Their source is therefore off limits.** No session writing this crate's code
opens, clones, reads or greps that repository. Not directly, not in a sibling
worktree, not through a subagent.

This is a narrower prohibition than the one in `bonsai-rs`. GPL-3.0 carries no
NonCommercial clause, so building and running their binary is unconstrained, on
any machine, including a commercial one. Only the *port* is constrained.

## Disclosure

A planning session on 2026-09-13, predating this repository, read their `src/` at
equation level while assessing feasibility, before the papers were to hand. The
plan it produced (`~/.claude/plans/radiant-prancing-minsky.md`) is not used as an
implementation source. It deliberately carries no equations, no variable names and
no constants from their code: only stage names, interfaces, I/O formats and
complexity, which are interface facts rather than expression.

`docs/SPEC.md` and every kernel in this crate are written by sessions that have
never opened the clone.

## The comparison harness

Black-box comparison against the reference implementation is permitted and
expected. Observing a program's behaviour by running it is protected under EU
Software Directive Art. 5(3) and does not create Adapted Material. GPL-3.0 places
no restriction on running the program at all.

The harness is private, lives outside this repository and is not part of the
crate. It builds their binary from the clone, runs both implementations, and
compares outputs. Whoever runs it needs `--help`, not their
source.

Comparison inputs are generated by this crate's own simulator (`src/simulate.rs`,
SPEC section on the SI S1.2 recipe), so both implementations are measured against
a ground truth neither produced.

Their `tests/` directory ships real 10x counts and reference outputs. Using those
files locally as an additional oracle is fine. **Vendoring them into this
repository is not.** They are GPL-3.0 content and redistributing them under MIT
would be the one actual licence breach available here.

## Rules this crate follows

1. Implementation reads `docs/SPEC.md`, not the PDFs and not their code. Every
   kernel cites the SI equation number it implements.
2. No mirroring of their module structure, function decomposition or naming.
3. No carrying over of their tuned constants. Every threshold is a named `const`
   with a doc comment saying where the number came from: an SI equation, or our
   own measurement with the date it was taken. Explicitly ours to determine, not
   theirs to donate: the variance grid bounds, the bin count, the solver
   tolerances, and any adaptive-grid schedule.
4. Output-level parity testing against a reference run is permitted, under the
   terms above.
5. The paper is cited in the crate documentation.

None of this is legal advice.
